🔧 Rotas de Ordem de Serviço

OS com Múltiplos Filtros

GET

BaseRoute/consulta/os/capa/?page=:pagina&limit=:quantidade&filtro1=:filtro1&filtro2=:filtro2
Filtros disponíveis para busca:
  • mecanico - Nome do mecânico
  • placa - Placa do veículo
  • numos - Número da OS
  • situacao_inicio e situacao_fim + tipo_data (ABERTURA ou SITUACAO)
  • situacao - Situação da OS
  • tipoos - Tipo da OS
  • modelo - Modelo do veículo
  • tipo_cliente - F (Física) ou J (Jurídica)
  • proprietario - Nome do cliente
  • dinamico - Parte do modelo e/ou placa
Exemplo:
BaseRoute/consulta/os/capa/?page=1&limit=20&plate=XXX 1234&mechanic=Rogerio

Cadastro de OS Completa (CAPA + ITENS)

POST

BaseRoute/cadastro/os/completa
Observação:

Esta rota é utilizada apenas para O.S feita do "zero". O body deve conter a capa (array com um objeto) e o array itens, que pode ser vazio.

Capa, itens, estoque e totais são gravados numa única transação: se qualquer parte falhar, nada é gravado.

Campos da capa:
  • placa ou veiculo - Obrigatório (um dos dois). Identifica o veículo. veiculo é o código do veículo e tem prioridade sobre placa. A placa é aceita com espaço, hífen ou sem separador (IKJ 3847, IKJ-3847, IKJ3847).
  • mecanico - Opcional. Código ou nome do mecânico. Precisa estar ativo e habilitado para O.S.
  • tipoos - Opcional. Código ou descrição do tipo de O.S. Se não for informado, assume GERAL.
  • situacao - Opcional. No momento a API só cadastra O.S como "Orçamento" (é o valor assumido quando não informado).
  • Demais campos da O.S (ex.: kms, assunto, problema_relatado, aexecutar, obs1) são opcionais e gravados como enviados.
Campos preenchidos pela API (não enviar):
  • codprop, proprietario e carro - Vêm sempre do cadastro do veículo: o proprietário atual do veículo e a descrição do modelo. Se forem enviados, são ignorados.
  • codigo - Número da O.S, gerado como o próximo número livre (mesma sequência do sistema principal). Enviar este campo gera erro.
  • abertura, dtsituacao e hrsituacao - Data/hora atual, quando não informados.
  • Totais da capa (valorpeca, valormo, valormost, descitens*, custoitens*) - Recalculados a partir dos itens.
Campos de cada item:
  • descricao - Obrigatório. Descrição do item.
  • quant - Obrigatório. Quantidade, maior que zero.
  • pecamo - Obrigatório. A = peça, B = mão de obra.
  • unidade - Unidade do item (ex.: PC). Mão de obra (B) usa MO ou ST (serviço de terceiros); peça (A) não pode usar MO nem ST.
  • valunit - Valor unitário.
  • pecacod - Código da peça/serviço cadastrado. Omitir ou enviar 0 para item avulso.
  • descval - Valor de desconto do item (opcional).

Não enviar id, numos, item, dtestoque nem usuario: são preenchidos pela API.

Exemplo de JSON:
{ "capa": [ { "placa": "IKJ 3847", "mecanico": 1, "tipoos": 1 } ], "itens": [ { "pecacod": 100, "descricao": "FILTRO DE OLEO", "pecamo": "A", "unidade": "PC", "quant": 2, "valunit": 50.00 }, { "descricao": "TROCA DE OLEO", "pecamo": "B", "unidade": "MO", "quant": 1, "valunit": 80.00 } ] }
Exemplo mínimo (só a capa):
{ "capa": [ { "placa": "IKJ 3847" } ], "itens": [] }
Erros comuns (HTTP 400):
  • Veículo não informado, não cadastrado ou sem cliente vinculado.
  • Mecânico ou tipo de O.S não encontrado, inativo ou não habilitado para O.S.
  • situacao diferente de "Orçamento".
  • Datas futuras, data de abertura em branco ou data da situação anterior à abertura.

Alteração de OS Completa (CAPA + ITENS)

PUT

BaseRoute/cadastro/os/completa/:codigo_da_OS
Parâmetros:
  • :codigo_da_OS - Código da OS a ser alterada
Header opcional:
  • X-Device-Id - Identificador da sessão/dispositivo do app, usado na checagem de concorrência.
Campos da capa:
  • alterou - true para gravar as alterações da capa. Sem ele, só os itens são processados.
  • dtHrInicio - Opcional (ISO 8601). Data/hora em que o app abriu a O.S para edição. Se outro usuário tiver alterado a O.S depois disso, a API recusa com 409.
  • situacao - Em Execução, Orçamento, Aguardando Peça, Concluída ou Cancelada. Faturada não é aceita (só pela rotina de faturamento). Ao mudar a situação sem enviar dtsituacao, a data da situação passa a ser hoje; ao concluir, a data de entrega é preenchida se estiver vazia.
  • mecanico e tipoos - Código ou descrição, com as mesmas regras do cadastro.
  • Demais campos da O.S que se deseja alterar.

veiculo, placa, codprop, proprietario e carro não mudam depois que a O.S foi aberta: se enviados, são ignorados.

Itens (cada um com acao):
  • "acao": "post" - Inclui um item novo (mesmos campos do cadastro).
  • "acao": "put" - Altera o item informado em id; envie só os campos que mudaram.
  • "acao": "delete" - Exclui o item informado em id.
  • Itens sem acao são ignorados.
Exemplo de JSON:
{ "capa": [ { "alterou": true, "dtHrInicio": "2026-11-12T14:30:00", "mecanico": 2, "situacao": "Em Execução" } ], "itens": [ { "acao": "put", "id": 1534, "quant": 3, "valunit": 55.00 }, { "acao": "post", "descricao": "ALINHAMENTO", "pecamo": "B", "unidade": "ST", "quant": 1, "valunit": 120.00 }, { "acao": "delete", "id": 1535 } ] }
Respostas de erro:
  • 400 - O.S já faturada, situação inválida, item que não pertence à O.S, mecânico/tipo inválidos ou datas inválidas.
  • 404 - O.S não encontrada.
  • 406 - A O.S está aberta em outro dispositivo.
  • 409 - A O.S foi alterada por outro usuário depois do dtHrInicio.
